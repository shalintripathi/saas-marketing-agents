# One real run: a feature launch from one brief

This is the unedited output of one CATALYST run. **Acme Uptime is a fictional company** made up for this example, and every fact about it is labeled as fictional wherever it appears.

**The brief:**

> "Plan and produce a product-launch campaign for our new Incident Timeline feature, targeting SRE leads at 50–500-person SaaS companies."

**What came back:** seven files from six specialists, all bound by one [`brand-context.md`](brand-context.md). The brand file only lists two proof points, so every claim the campaign wanted but couldn't back up shows as a `[NEEDS INPUT: ...]` marker instead of a made-up number. There are 50 of them across the seven files. That's the point of the example: you see exactly which facts you still have to supply.

| File | What it is | Agents |
|---|---|---|
| [00-catalyst-routing-plan.md](deliverables/00-catalyst-routing-plan.md) | Mode choice (Sprint), who gets which task, launch sequence, quality gate | CATALYST Orchestrator, Product Launch Manager |
| [01-positioning-and-messaging.md](deliverables/01-positioning-and-messaging.md) | Positioning, message house, capability claim register | Positioning Strategist, Messaging Architect |
| [02-launch-blog.md](deliverables/02-launch-blog.md) | Launch blog: brief, answer-first draft, FAQ | Blog Strategist, Copywriter |
| [03-launch-email.md](deliverables/03-launch-email.md) | Customer email: 3 subject lines, preview text, one CTA | Email Copywriter |
| [04-linkedin-posts.md](deliverables/04-linkedin-posts.md) | 3 LinkedIn drafts (a human posts them) and a first-hour plan | LinkedIn Strategist |
| [05-aeo-geo-checklist.md](deliverables/05-aeo-geo-checklist.md) | AI-search checklist applied to the actual blog draft | AI Search Optimizer |
| [06-measurement-plan.md](deliverables/06-measurement-plan.md) | Pre-launch tracking check, metric definitions, tripwire | Performance Analyst |

Summary from the run itself: [deliverables/SUMMARY.md](deliverables/SUMMARY.md).

**Try the same thing on your product:** install the plugin, copy [`templates/brand-context.md`](../../templates/brand-context.md) into your project as `brand-context.md`, fill it in, and send your own launch brief. The fuller your brand file, the fewer `[NEEDS INPUT]` markers you get back.
